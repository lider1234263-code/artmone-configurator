# Правила роботи з ArtMone configurator

1. Джерело істини — GitHub `lider1234263-code/artmone-configurator`, гілка `main`, а не старі ZIP або чат.
2. На початку нового чату прочитати `PROJECT_CHECKPOINT.md`, `HANDOFF.md` та поточний `index.html`; перевірити актуальний SHA `main`.
3. Перед зміною зафіксувати clean/dirty status. Не перезаписувати сторонні або непідтверджені зміни.
4. Звичайний шлях публікації: GitHub `main` → автоматичний Vercel deploy → live `https://artmone-configurator-na4n.vercel.app/`.
5. Не використовувати ручний ZIP-deploy і не повертатися до `assets/import/chunk_*.txt`.
6. За замовчуванням правки мають працювати на desktop і mobile. Елементи, явно позначені як mobile-only, не переносити на desktop.
7. Не змінювати бізнес-правила та ціни без прямої команди користувача. Канонічні правила записані в `PROJECT_CHECKPOINT.md` і реалізовані в `index.html`.
8. Не запускати image generation без прямого запиту створити, перефарбувати або відредагувати зображення.
9. Галерея одного AM-коду вважається готовою лише за наявності рівно 11 валідних WebP 1600×1600 з очікуваними назвами.
10. Не говорити «готово» до commit/push, завершеного Vercel deployment і live-перевірки.
11. Після кожного завершеного етапу оновити `PROJECT_CHECKPOINT.md` і `HANDOFF.md`: commit, виконані зміни, невирішені питання та один точний наступний крок.
12. Логотипи клієнтів не комітити в репозиторій і не виводити в logs.
